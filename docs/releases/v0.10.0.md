# Aether v0.10.0 — The Cockpit & the Self-Building Loop

**Released:** 2026-06-04 · **Previous tag:** `v0.9.4` (2026-05-20)

> Version proposed by the repo-front-v2 lane and **pending Director confirmation**.
> `v0.6.0`–`v0.9.4` already exist as tags, so the next minor is `v0.10.0`; the
> conservative alternative is `v0.9.5`. See the PR body for the full rationale.

This is the release where Aether stopped being only a thing you operate and
started being a thing that watches itself — proposes its own next steps, and hands
a human the pen. Two arcs landed: **the cockpit** (a scene you direct by voice) and
**the self-building loop** (`gaps → proposals → drafts`, human-gated end to end).

---

## The arc

### Cockpit day

Sprint 6 was a direction shift (`#119`): away from a drawer of content apps and
toward a **scene-driven cockpit**. The RAVEN_AVP scene server was vendored as a
supervised daemon (`#122`); a WebSocket-plus-IPC scene transport wired it into the
shell (`#124`); and a new `visualizer` node — a *Mixer* — became the bridge that
reads live mesh state and composes it into scene panels (`#126`). Then voice took
the wheel: `visualize` ("show me the mesh") routed a spoken summons through
`raven → visualizer.render` (`#127`).

From there the cockpit filled in. A lanes sensor surfaced live Claude Code sessions
per git worktree (`#130`, `#133`, `#136`, `#143`); an interactive mesh topology view
arrived (`#138`) and its edges became **inspectable**, not just drawn — hover to see
the surface an edge authorizes, click to open the relationship (`#161`). Panels gained
a **re-summon pulse** and scroll-into-view (`#149`), durable **chat transcripts** with
a Chats view (`#147`), and finally **drag-to-reorder arrangement that survives restarts**
(`#166`). The day's hard-won lessons were banked in the governance log (`#141`).

### The loop, and the Architect

The second arc is the one that changes what Aether *is*. A **gap sensor** (`#145`)
gave raven a `report_gap` voice tool and a persistent `intents` node to record what
the system *couldn't* do — a durable, append-only ledger of its own blind spots. The
visualizer learned to **show those gaps** as a panel (`#153`). Gaps then grew a
**lifecycle** — `open` vs `closed`, event-sourced — so the ledger reflects what's been
answered, not just what was ever missing (`#164`).

With a ledger to reason over, raven began to **propose**. `review_gaps` (`#158`)
reads the gap log back through the mesh and pitches one to three concrete lanes — each
named with the gap it closes and what it would touch. It proposes *only*: it never
offers to build, spawn, or schedule. Then **rung 1** (`#168`): an accepted proposal
becomes a paste-ready, house-format lane prompt written to disk via `draft_lane`. The
loop closes — `gaps → proposals → drafts` — and a human is the gate at every rung.

This is the first brick of what the changelog calls the **Architect era**: the system
helping author its own next lane, with a person reading, approving, and shipping.

### Data caught up too

Mail learned to **open** the latest message in Mail.app via LaunchServices (`#154`,
closing the gap sensor's very first recorded capture), and the calendar answered
"what's on my agenda" by both voice and panel (`#170`).

## Upgrade / run

No migration steps. Pull `main`, then from the repo root:

```sh
pnpm install
pnpm -r build
cd shell && pnpm dev
```

See the [README quickstart](../../README.md#quickstart) for prerequisites and the
`.env.local` voice-key note. Full per-PR detail is in
[CHANGELOG.md](../../CHANGELOG.md).
