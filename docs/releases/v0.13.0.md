**Released:** 2026-06-12 · **Previous tag:** `v0.12.0` (2026-06-11)

## The arc

### Lane A — the node (`#333`)

The `music` mesh node is a Spotify playback Actor: five Actor surfaces
(`play` — query or URI, query resolves via search; `pause`; `skip` next|prev;
`queue`; `search`) plus a `now_playing` sensor surface that polls at 3s only
while playback is active or recent, reads live on demand when idle, and emits
a `host_notifications.notify` change event on observed track changes. Auth is
Authorization Code with **PKCE** — `SPOTIFY_CLIENT_ID` from `.env.local`, no
client secret anywhere: the first Actor call opens the system browser, a
one-shot loopback listener on `127.0.0.1:8898/callback` catches the code, and
the rotating refresh token lands owner-only (0600) under
`AETHER_DATA_DIR/music/`, so restarts re-authenticate without a browser.
Missing client id, missing token, and no active Spotify Connect device all
deny loudly by name — `music_no_client_id`, `music_not_authenticated`,
`music_no_active_device` — never hang.

### Lane B — voice + face, and #225 closes (`#335`)

raven gained the `music_tool` group (`play_music` — empty query resumes;
`pause_music`; `skip_track`; `queue_music`; `whats_playing`): thin
`mesh_invoke` wrappers that are deliberately **not confirm-gated** (media
controls are non-destructive and instantly reversible — the standing #225
ruling) and return pre-written `spoken` lines, so the node's named denies
surface as friendly speech instead of error strings read aloud. The Viewer
gained the Music app — album art, track/artist/album, play state, a progress
bar interpolated between its 3s `now_playing` polls — listed in the Console
like every other app. Node touches: `now_playing` carries `album_art_url`,
bare `play` resumes via Spotify's bodyless player/play, and the per-track
toast went opt-in behind `MUSIC_TOAST=1`. This lane closed **#225**, the
end-to-end pipeline validation case.

### Lane C — memory, library, and touch (`#338`)

Two library reads joined the node — `music.playlists` and
`music.recently_played` — and three voice tools joined raven: `play_playlist`
(fuzzy match: exact, substring, then difflib close-match; a miss is a spoken
line naming what was heard), `play_last_song`, and `list_playlists`. And the
Music app got buttons: prev / play-pause / next over the existing
`shell → music.{skip,pause,play}` edges, under the new **apps-interactive
ADR** (2026-06-11): shell apps MAY invoke Actor surfaces over their own
manifest edges — they are MeshApps, already on the signed-envelope path —
while panels (Raven-rendered visualizer surfaces) stay display-only until a
panel-interaction protocol is designed. The #225-era "no buttons, voice is
the remote" framing is superseded *for apps*; voice is no longer the only
remote, just the one that works from anywhere.

### READY TO TEST — the gate learns to announce itself (`#341`)

R1 of the revision loop (#339 holds the banked design for the rest): at the
existing AT GATE detection point, the shell now emits ONE
`host_notifications.notify` toast per gate arrival — "Lane N is ready to
test" — keyed by the gate-report comment's `created_at`, so a re-gate toasts
again while refreshes stay silent. raven gained two read-only tools:
`whats_ready_to_test()` folds the spawn ledger and reads each live lane's
issue thread to speak who's waiting, and `read_test_steps(number)` fetches
the latest gate report, extracts its smoke section, and speaks the steps as a
numbered walkthrough. No relay or gate-protocol changes — additive surfacing
only; the protocol changes are #339's design session, not this lane.

## Upgrade / run

No migration steps. Pull `main`, then from the repo root:

```sh
pnpm install
pnpm -r build
cd shell && pnpm dev
```

One optional capability gained config this release: music needs
`SPOTIFY_CLIENT_ID` in `.env.local` (a Spotify developer app with redirect
URI `http://127.0.0.1:8898/callback` registered; **no client secret** — auth
is PKCE, and the first music ask opens a one-time browser grant). Unset, the
node boots degraded and denies by name rather than failing the mesh.
`MUSIC_TOAST=1` opts back into the per-track notification if you want it —
the Music app is the visible surface by default. Everything else is as
v0.12.0: `AETHER_GITHUB_TOKEN` for the board, `tmux` on the PATH for lanes,
`AETHER_DRAFT_MODEL` for the composer.

See the [README quickstart](../../README.md#quickstart) for prerequisites and
the `.env.local` notes. Full per-PR detail is in
[CHANGELOG.md](../../CHANGELOG.md).
